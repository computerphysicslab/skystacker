### TECHNICAL SPECIFICATION: CROSS-PLATFORM CLI INTEGRATION AND AUTOMATION ARCHITECTURE FOR OBSERVATORY IMAGE STACKING \#\#\#\#\# 1\. Architecture & Automated Core Processing Pipeline In modern automated observatories and high-throughput astronomical imaging facilities, processing vast volumes of deep-sky sub-exposures requires robust, low-latency data pipelines. Contemporary detector architectures, including high-resolution Complementary Metal-Oxide-Semiconductor (CMOS) and Charge-Coupled Device (CCD) arrays, regularly generate 60+ megapixel sub-exposures per frame. When executing extended observational campaigns, raw dataset volumes routinely scale to hundreds of gigabytes per imaging session. To process these gigabyte-scale datasets without operational bottlenecks, relying on graphical user interface (GUI) execution loops or cloud-based microservice API calls introduces unacceptable bandwidth latency, network overhead, and dynamic resource consumption. Establishing a local-first, headless Command Line Interface (CLI) engine—engineered around statically compiled native binaries and concurrent execution runtimes such as Go 1.20+—is an architectural imperative. By executing statically compiled, multi-threaded binaries directly on local edge hardware or observatory control nodes, spatial tile streaming and parallel worker pools can saturate available CPU cores while maintaining strict, deterministic memory bounds. This architectural approach eliminates intermediate physical disk write operations, desktop GUI runtime dependencies, and dynamic heap allocation thrashing, establishing a scriptable foundation for high-fidelity scientific signal extraction.  \[ Input Raw Dataset: FITS, FITS.FZ, RAW, TIFF, XISF \] \| v 1\. The catalog indexer validates spatial dimensions, sensor gain, exposure duration (DATE-OBS, EXPOSURE), and timestamp metadata while filtering out corrupt, incomplete, or truncated files. 2\. **Calibration Preprocessing:** Raw light sub-exposures undergo subtraction of thermal dark current and readout electronic offset via pre-integrated Master Dark and Master Bias/Flat-Dark frames, followed by division by normalized Master Flat frames to eliminate vignetting and optical path dust attenuation. 3\. **Alignment & Coordinate Grid Verification:** Spatial registration algorithms verify celestial bounds, calculating spatial offsets or evaluating World Coordinate System (WCS) transformation matrices to confirm accurate registration alignment prior to pixel aggregation. 4\. **Parallel Spatial Tile Accumulator:** To bound heap allocations and garbage collection overhead, full-frame spatial planes are partitioned into uniform, discrete spatial tiles (e.g., \$1024 \\times 1024\$ pixels). Thread-safe worker pools stream pixel columns from disk into pre-allocated 32-bit floating-point (float32) memory buffers managed via Go sync.Pool allocators. 5\. **Statistical Outlier Rejection & Integration:** Pixel values along the temporal array of each spatial tile undergo statistical filtering (such as Winsorized Sigma Clipping or Percentile Clipping) to eliminate satellite trails, cosmic rays, and hot pixels before computing the final temporal pixel accumulation. 6\. **Scientific Encoding & Visualization Rendering:** The integrated 32-bit floating-point array is encoded directly into uncompressed IEEE 754 float32 scientific files (FITS or TIFF with SampleFormat=3). Concurrently, non-linear preview renderings (Inverse Hyperbolic Sine or Midtone Transfer Function) are generated for visual validation. 7\. **Session Telemetry & Audit Reporting:** System execution metrics, rejection statistics, spatial Half Flux Diameter (HFD) measurements, and plate solve parameters are exported into machine-readable JSON telemetry logs and INI control files to maintain strict scientific auditability. \#\#\#\#\#\# Core ASTAP 5-Step Stacking Workflow The native ASTAP core stacking engine executes an optimized 5-step integration sequence designed for memory-bounded execution: 1\. **Master Flat Generation:** Individual flat frames are combined into an arithmetic average. Combined flat-dark (or bias) frames are subtracted to establish a calibrated signal baseline. The master flat undergoes 2x2 neighborhood mean spatial normalization to equalize the Bayer matrix response: \$\$\\text{Master Flat} \= \\frac{1}{N} \\sum \\text{Flats} \- \\frac{1}{N} \\sum \\text{Flat-Darks}\$\$ 2\. **Master Dark Generation:** Individual dark frames captured at matching sensor temperatures and exposure durations are combined into an averaged Master Dark frame: \$\$\\text{Master Dark} \= \\frac{1}{N} \\sum \\text{Darks}\$\$ 3\. **Pure Signal Extraction (Dark Subtraction):** From each raw light sub-exposure, the Master Dark is subtracted in-memory to isolate the astronomical photon signal from thermal dark current accumulation and baseline readout electronic offset. 4\. **Optical Normalization (Flat Division):** Each dark-subtracted light sub-exposure is divided by the Master Flat frame to correct for optical vignetting and dust spot shadows. 5\. **In-Memory Frame Combination:** Corrected light frames are aligned and combined into the final master stack using arithmetic average or sigma-clip mean rejection methods. Steps 3, 4, and 5 execute strictly within memory buffers; no intermediate calibrated frames are written to physical disk storage, maximizing overall I/O throughput. \#\#\#\#\#\# Memory Management & Garbage Collection Dynamics In concurrent processing engines written in managed runtimes like Go, streaming multi-gigabyte spatial arrays can trigger severe performance bottlenecks due to Garbage Collection (GC) thrashing. Loading a 100-frame stack of 60-megapixel sub-exposures at 32-bit float precision represents over 24 Gigabytes of continuous allocation. To eliminate GC pause latency, the parallel spatial tile accumulator allocates uniform slice buffers ( \$1024 \\times 1024 \\times 4\\text{ bytes} \= 4\\text{ MB}\$ per float32 tile) managed through Go sync.Pool rings. Thread-safe worker pools retrieve pre-allocated slice pointers from the pool, fill them with tile pixel streams, perform spatial integration, and return the slice pointers to the pool. Because memory buffers are recycled across spatial tiles rather than freed, memory consumption remains bounded strictly by thread concurrency rather than sub-exposure stack depth, eliminating heap allocation overhead during execution. \| Pipeline Stage \| Input Artifacts \| Processing Memory State \| Generated Output Artifacts \| \| \------ \| \------ \| \------ \| \------ \| \| **1\. Calibration Mathematics, Star Registration, and Stacking Methods The physical extraction of faint astronomical signals from raw digital sensor outputs requires rigorous mathematical isolation of signal components. Photons emitted by celestial targets arrive at the detector as a Poisson point process, accompanied by terrestrial optical distortion, sensor thermal buildup, and electronic read noise. Correcting these systematic perturbations and maximizing the signal-to-noise ratio (SNR) relies on precise matrix operations and statistical filtering along the temporal axis. \#\#\#\#\#\# Calibration Mathematics Sensor calibration isolates astronomical photon flux from thermal and electronic noise sources. The mathematical expression governing sub-frame calibration is defined as: \$\$I\_{\\text{calibrated}}(x,y) \= \\frac{I\_{\\text{light}}(x,y) \- I\_{\\text{dark}}(x,y)}{I\_{\\text{flat}}(x,y) \- I\_{\\text{bias}}(x,y)} \\cdot \\bar{I}*{\\text{flat}}\$\$ Where: \* \$I*{\\text{light}}(x,y)\$ represents the raw target sub-exposure intensity at spatial coordinates \$(x,y)\$ . \* \$I\_{\\text{dark}}(x,y)\$ represents the Master Dark frame intensity, isolating thermal charge accumulation and fixed-pattern dark current. \* \$I\_{\\text{bias}}(x,y)\$ (or flat-dark) isolates the uniform electronic readout noise offset. \* \$I\_{\\text{flat}}(x,y)\$ represents the Master Flat field intensity, mapping optical throughput variations, vignetting, and dust attenuation. \* \$\\bar{I}*{\\text{flat}}\$ is the scalar mean intensity of the Master Flat frame, used to normalize the output dynamic range. By executing this operation, non-astronomical sensor artifacts are mathematically eliminated. Furthermore, when integrating \$N\$ calibrated sub-exposures, uncorrelated stochastic noise sources (shot noise, read noise) sum in quadrature ( \$\\sigma*{\\text{total}} \= \\sqrt{N} \\cdot \\sigma\_{\\text{sub}}\$ ), while target signal sums linearly ( \$S\_{\\text{total}} \= N \\cdot S\_{\\text{sub}}\$ ). This establishes the standard theoretical scaling law: \$\$\\text{SNR}*{\\text{stack}} \= \\sqrt{N} \\cdot \\text{SNR}*{\\text{sub}}\$\$ \#\#\#\#\#\# Star-Based Alignment & Registration (Quad Matching Algorithm) Frame alignment is achieved via a star pattern matching algorithm based on geometric quad structures.  Star A \*--------------------\* Star B \\ / \\ Distance 1-4 / \\ / \*------------\* Star C Star D \[ 4 Star Detections \= 1 Irregular 2D Tetrahedron (Quad) \] \[ 6 Inter-Star Distances \-\> Unique 6-Digit Invariant Hash \]  1\. **Quad Formation:** The engine identifies prominent stellar centroids within an image and groups four adjacent star detections into an irregular 2D tetrahedron (kite structure). 2\. **Hash Code Generation:** Six internal geometric distances between the four stars are calculated. These six relative spatial metrics are combined to form a scale-, rotation-, and translation-invariant hash code. 3\. **Database & Reference Matching:** Hash codes generated from target sub-exposures are matched against reference frame quads or an onboard star catalog (such as Gaia-derived catalogs) using a least-squares fitting routine. 4\. **Algorithm Configuration Parameters:** \* **Maximum Star Count (** **\-s** **):** Restricts quad construction to the brightest star detections (default: \$500\$ ) to balance solve speed and registration stability. \* **Hash Code Tolerance (** **\-t** **):** Sets the maximum allowable deviation when matching quad geometric hash metrics (default: \$0.007\$ ). \* **Minimum HFD Threshold Filter (** **\-m** **/** **Ignore stars \< HFD** **):** Excludes single-pixel hot pixels and high-frequency noise spikes by filtering out detections below \$0.8\$ pixels for stack registration or \$\< 1.5''\$ arcseconds for plate solving. \#\#\#\#\#\# Evaluation of Stacking Integration Algorithms \* **Sum Integration:** Computes the unweighted cumulative sum of pixel intensities across \$N\$ sub-exposures: \$\$I\_{\\text{sum}}(x,y) \= \\sum\_{i=1}^{N} I\_i(x,y)\$\$ *Evaluation:* Sum integration preserves absolute raw photon counts and expands overall dynamic range, but it retains non-Gaussian transient artifacts (satellite trails, cosmic rays) and requires floating-point storage to prevent bit overflow. \* **Arithmetic Mean Integration:** Computes the average temporal pixel intensity: \$\$I\_{\\text{mean}}(x,y) \= \\frac{1}{N} \\sum\_{i=1}^{N} I\_i(x,y)\$\$ *Evaluation:* Achieves the theoretical maximum SNR improvement factor ( \$\\sqrt{N}\$ ) for ideal Gaussian noise distributions. However, it is highly sensitive to non-Gaussian transient outliers, which permanently distort the mean. \* **Median Integration:** Selects the central value from a temporally sorted pixel array: \$\$I\_{\\text{median}}(x,y) \= \\text{median}\\left(\\{I\_1(x,y), I\_2(x,y), \\dots, I\_N(x,y)\\}\\right)\$\$ *Evaluation:* Completely suppresses extreme transient outliers without threshold parameters. However, for normal distributions, unclipped median stacking incurs a statistical efficiency loss of \~20%, yielding an SNR scaling factor of only \$0.80\\sqrt{N}\$ . \* **Percentile Clipping:** Evaluates rank-ordered percentile positions ( \$P\_{\\text{low}}, P\_{\\text{high}}\$ ) across the temporal array to drop extreme boundary values prior to mean integration. *Evaluation:* Designed specifically for small sub-exposure sets ( \$N \\le 6\$ ) where standard deviation estimations are statistically unreliable. Delivers moderate outlier rejection with an SNR factor of \$\\sim 0.85\\sqrt{N}\$ . \* **Sigma-Clipped Mean Integration:** Evaluates variance dispersion around a median estimator ( \$\\tilde{I}\$ ) and rejects pixels falling outside specified standard deviation limits ( \$\\tilde{I} \\pm k \\cdot \\sigma\$ ): \$\$I\_{\\text{sigma}}(x,y) \= \\frac{1}{\|M\|} \\sum\_{i \\in M} I\_i(x,y) \\quad \\text{where} \\quad M \= \\{ I\_i \\mid \\tilde{I} \- k\_{\\text{low}}\\sigma \\le I\_i \\le \\tilde{I} \+ k\_{\\text{high}}\\sigma \\}\$\$ *Evaluation:* Provides strong rejection of satellite tracks and cosmic rays while preserving near-optimal SNR performance ( \$\\sim 0.95\\sqrt{N}\$ ) on large datasets ( \$N \\ge 31\$ ). \* **Winsorized Sigma Clipping:** Replaces rejected extreme outlier values with the nearest accepted boundary value (Winsorization) prior to computing standard deviation and final mean values: \$\$\\text{If } I\_i \> \\tilde{I} \+ k\_{\\text{high}}\\sigma\_{\\text{win}}, \\quad \\text{set } I\_i^{\\text{win}} \= \\tilde{I} \+ k\_{\\text{high}}\\sigma\_{\\text{win}}\$\$ *Evaluation:* Prevents variance underestimation and maintains sample symmetry on moderate sample sizes ( \$10 \\le N \\le 30\$ ), achieving near-theoretical SNR scaling ( \$\\sim 0.98\\sqrt{N}\$ ). \| Stacking Integration Method \| Mathematical Formula Post-Processing Pipeline & Automated Diagnostic Metrics Automated observatory installations require real-time post-processing and diagnostic image evaluation to ensure scientific data integrity. Unattended systems must automatically convert single-plane raw sensor metrics into calibrated color space representations, perform background neutralization, and extract precise quantitative metrics to track optical alignment, sensor tilt, atmospheric seeing, and transient astronomical phenomena. \#\#\#\#\#\# Demosaicing & One-Shot Color (OSC) Processing Raw images captured by color digital single-lens reflex (DSLR) and One-Shot Color (OSC) cameras feature a Bayer color filter array (CFA) matrix across the physical pixel array. Reconstructing full-color RGB representations requires dedicated debayering routines: \* **AstroC (Saturated Star Reconstruction):** Similar to bilinear interpolation, but specifically evaluates saturated stellar cores. If star pixels reach detector full-well saturation, the algorithm reconstructs balanced RGB channel ratios to prevent artificial color tinting in star cores. \* **AstroM (White Stars / Undersampled):** Evaluates imbalance across the 4-pixel Bayer block ( \$R, G\_1, G\_2, B\$ ). For undersampled images or small stacks where color sampling is unstable, it derives a monochrome luminance value, rendering stars neutral white to eliminate chromatic artifacts. \* **AstroSimple (© Han Kleijn, CC BY 4.0):** Extracts discrete \$R, G\_1, G\_2, B\$ color information within a localized \$2 \\times 2\$ pixel neighborhood without cross-channel spatial bleeding. Highly effective for astronomical images, preserving high-frequency details while minimizing color artifacts around star edges. \* **Standard Bilinear:** Computes channel interpolation by averaging pixel values across a \$3 \\times 3\$ grid. Effective for smooth gradient transitions, but can introduce spatial blurring in compact stellar profiles. \#\#\#\#\#\# Post-Processing Pipeline Operations \* **Background Equalization & Gradient Removal:** Linear and higher-order polynomial planar background subtraction algorithms remove synthetic gradients caused by light pollution, twilight skyglow, or lunar interference. Spatial regions free of deep-sky structure are evaluated to compute a neutral background plane. \* **Color Calibration & Smoothing:** Auto-leveling routines adjust global RGB channel weights, neutralizing the background sky baseline to a uniform dark gray while setting mean star colors to a neutral white balanced point. Color smoothing routines blur high-frequency de-mosaic chromatic noise in non-stellar background regions while preserving structural luminance data. \* **Non-Linear Visualization Stretch:** Raw 32-bit floating-point astronomical stacks feature compressed dynamic ranges centered near sensor black levels. The visualization engine applies non-linear stretches—such as the Inverse Hyperbolic Sine (AsinhStretch) and Midtone Transfer Functions (MTF)—to render low-contrast nebulae and galaxy structures visible in preview files without clipping bright stellar cores. \#\#\#\#\#\# Automated Image Quality Diagnostics The post-processing framework continuously monitors optical system health using the following automated metrics:  \[ AREA 1A: Corner Top-Left \] \[ AREA 2A: Top-Center \] \[ AREA 3A: Corner Top-Right \] \\ \| / \\ \| / \[ AREA 1B: Left-Center \] \[ AREA 2B: CENTER \] \[ AREA 3B: Right-Center \] / \| \\ / \| \\ \[ AREA 1C: Corner Bottom-Left \] \[ AREA 2C: Bottom-Center \] \[ AREA 3C: Corner Bottom-Right \] \* OFF-AXIS ABERRATION DELTA \= HFD\_out (Outer Areas 75%+) \- HFD\_centre (Area 2B) \* CORNER TILT PERCENTAGE \= 100% \* ( HFD\_worst\_corner \- HFD\_best\_corner ) / HFD\_median  \* **Focus & Sharpness (Half Flux Diameter \- HFD):** Computes stellar flux distributions to determine the diameter in pixels containing 50% of a star's total cumulative energy. Median HFD is calculated across the full sensor plane to track focus drift and seeing conditions. \* **Sensor Tilt Evaluation (9-Area Octagon & 3-Corner Triangle):** The image sensor is segmented into nine distinct spatial zones (Corners 1A, 3A, 1C, 3C; Edges 2A, 1B, 3B, 2C; Center 2B). Tilt is evaluated by computing the percentage deviation between the best and worst corner median HFD values: \$\$\\text{Tilt \\%} \= 100 \\times \\frac{\\text{HFD}*{\\text{worst\\\_corner}} \- \\text{HFD}*{\\text{best\\\_corner}}}{\\text{HFD}*{\\text{median}}}\$\$ Tilt Severity Classification Scale: \* **\$\< 5\\%**\$ **:** None (Optimal optical alignment) \* **\$5\\% \- 10\\%**\$ **:** Almost None (Negligible tilt offset) \* **\$10\\% \- 15\\%**\$ **:** Mild (Acceptable operational threshold) \* **\$15\\% \- 20\\%**\$ **:** Moderate (Noticeable optical degradation) \* **\$20\\% \- 30\\%**\$ **:** Severe (Requires mechanical tilt adjustment) \* **\$\> 30\\%**\$ **:** Extreme (Critical optical mis-alignment) For tilt adapters equipped with three 120° adjustment push-pull screws, a symmetrical 3-corner triangular analysis mode evaluates three 120° radial segments (excluding the inner 25% center), mapping HFD variances directly to physical adapter adjustment screws. \* **Optical Aberration Metrics:** Computes off-axis aberration as the delta between outer field HFD and central field HFD ( \$\\Delta\\text{HFD} \= \\text{HFD}*{\\text{out}} \- \\text{HFD}*{\\text{centre}}\$ , where \$\\text{HFD}*{\\text{out}}\$ measures stars at \$\\ge 75\\%\$ radial distance from sensor center). Spatial HFD variations are rendered visually using 2D HFD contour maps and Voronoi diagram partitions (HFD diagram). \* **Star Roundness (Aspect Ratio):** Stellar profiles are divided by a rotating 180-degree split line. The ratio of maximum to minimum average pixel distances across the split boundary yields the aspect ratio ( \$1.0\$ indicating a perfectly circular profile). \* **Automated Astronomical Outputs:** \* **MPC1992 Minor Planet Report Lines:** Formats detected astrometric positions into standard 80-column Minor Planet Center text blocks, ready for submission. \* **Gaia-Based Nova Candidate Identification:** Compares detected point sources against online Gaia DR3 catalog entries down to magnitude 21\. Stars missing from the catalog or exhibiting an anomalous magnitude increase ( \$\> 1.0 \\text{ mag}\$ ) are automatically flagged and annotated as potential novae candidates. \* **Sky Quality Meter (SQM) Measurement:** Calculates absolute sky background brightness in \$\\text{mag/arcsec}^2\$ by calibrating background flux levels against catalog star magnitudes, applying Pickering airmass formulas to compensate for atmospheric extinction: \$\$\\text{Airmass} \\approx \\text{Pickering}(h) \\implies \\text{Extinction} \= 0.2811 \\times \\text{Airmass}\$\$ The suite of image diagnostics and post-processing tools directly informs execution routines, leading to the CLI flag reference specifications and multi-platform binary deployment patterns. \#\#\#\#\# 4\.
